# Dabbar بوت — تتبع المصاريف والديون بالصوت على تليجرام

## 1) Supabase
- افتح مشروعك في Supabase → SQL Editor → New Query
- الصق محتوى `sql/schema.sql` وشغّله (Run)
- لو عندك مشروع قديم شغّال بالفعل، السكريبت آمن يتشغّل تاني (`create table if not exists`) وهيضيف بس الجداول الجديدة: `debt_settlements` و `users`

## 2) رفع الكود
- ارفع الفولدر ده كامل على GitHub repo جديد
- من Vercel: New Project → استورد الـ repo ده → Deploy

## 3) Environment Variables (في إعدادات المشروع على Vercel)
| اسم المتغير | القيمة منين | مطلوب؟ |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | من BotFather على تليجرام | ✅ |
| `GROQ_API_KEY` | من console.groq.com → API Keys | ✅ |
| `SUPABASE_URL` | من Supabase → Project Settings → API | ✅ |
| `SUPABASE_SERVICE_ROLE_KEY` | من Supabase → Project Settings → API (Service Role، مش Anon) | ✅ |
| `CRON_SECRET` | أي قيمة سرّية تختارها إنت | اختياري، بس ننصح بيه (تأمين الـ cron endpoint) |
| `GROQ_TEXT_MODEL` | افتراضيًا `llama-3.3-70b-versatile` | اختياري |
| `ADMIN_TELEGRAM_ID` | الـ Telegram user id بتاعك إنت (الأدمن) — ابعت أي رسالة لـ `@userinfobot` عشان تعرفه | ✅ (عشان تقدر تفعّل اشتراكات) |
| `SUBSCRIPTION_DAYS` | مدة الاشتراك بالأيام بعد كل تفعيل، افتراضيًا `30` | اختياري |
| `SUBSCRIPTION_PRICE_EGP` | السعر اللي بيتعرض للمستخدم، افتراضيًا `99` | اختياري |
| `INSTAPAY_LINK` | رقم/رابط الإنستا باي بتاعك اللي بيتعرض للمستخدم | ✅ |
| `ADMIN_CONTACT_USERNAME` | يوزرك على تليجرام (`@اسمك`) عشان الناس تبعتلك سكرين شوت التحويل | ✅ |

ملاحظة: البوت بيستخدم Groq بس لكل حاجة — تفريغ الصوت (`whisper-large-v3`) واستخراج المبلغ والفئة (`llama-3.3-70b-versatile`).

بعد ما تضيف المتغيرات، اعمل **Redeploy** للمشروع عشان القيم تتفعّل (ولازم تعمل Redeploy كمان أول مرة عشان الـ Cron Job في `vercel.json` يتسجّل).

## 4) ربط الـ Webhook (مرة واحدة بس)
افتح الرابط ده في المتصفح بعد ما تستبدل القيم:
```
https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/setWebhook?url=<VERCEL_URL>/api/telegram-webhook
```
مثال:
```
https://api.telegram.org/bot7123456789:AAExxxxx/setWebhook?url=https://dabbar-bot.vercel.app/api/telegram-webhook
```
لازم يرجعلك `{"ok":true,...}`.

## 5) جرب البوت
- افتح البوت في تليجرام، ابعت `/start` عشان تشوف كل الأوامر
- ابعت فويس نوت أو رسالة زي "صرفت 50 جنيه أكل" (بيتسجل كمصروف)
- ابعت رسالة زي "عطيت محمد 200 جنيه" أو "استلفت من سارة 100 جنيه" (بيتسجل كدين)

## ⏰ التوقيت
- البوت مظبوط يشتغل بتوقيت **القاهرة** أوتوماتيك (مش محتاج تعمل حاجة) — ده بيأثر على حساب "بداية اليوم" و"بداية الشهر" في كل التقارير والكرون اليومي
- لو حبيت تغيّر التوقيت لأي منطقة تانية، ضيف `TZ` في Environment Variables على Vercel (مثلاً `Europe/London`) وهياخد الأولوية على القيمة الافتراضية

## 📜 كل الأوامر المتاحة
| الأمر | بيعمل إيه |
|---|---|
| `صرفت 50 جنيه أكل` (صوت أو نص) | يسجل مصروف |
| `عطيت محمد 200 جنيه` / `استلفت من سارة 100 جنيه` | يسجل دين |
| `خلصت مع محمد` | يصفّر الرصيد مع محمد (تسوية) — التاريخ القديم بيفضل محفوظ لكن الصافي بيرجع صفر |
| `تقرير` | تقرير شهري كامل: إجمالي، تفصيل بالفئات، رسم بياني، مقارنة بالشهر اللي فات، وأعلى 3 عمليات |
| `تقرير الأسبوع` | ملخص مختصر لآخر 7 أيام |
| `ديون` | ملخص صافي الديون مع كل الناس |
| `ديون محمد` | كل تفاصيل العمليات مع محمد بالتحديد (مش الصافي بس) |
| `دور على قهوة` / `ابحث عن قهوة` / `فين صرفت على قهوة` | يدورلك في كل مصاريفك على أي كلمة (وصف أو فئة) ويطلعلك النتايج + الإجمالي |
| `صدّر البيانات` | يبعتلك ملف CSV فيه كل المصاريف والديون (يفتح كويس على Excel) |

## ⏰ التقارير والتذكيرات التلقائية (Cron Job)
- في `vercel.json` كرون واحد بيشتغل يوميًا الساعة **9 مساءً بتوقيت القاهرة** (`0 19 * * *` بتوقيت UTC — القاهرة UTC+2)، وبينادي `/api/cron-daily`
- كل يوم: بيبعت لكل مستخدم (لو عمل أي عملية النهاردة) ملخص آخر اليوم + تذكير لو عنده ديون من غير تسوية أكتر من 30 يوم
- يوم الجمعة (نهاية الأسبوع): بيتبعت كمان التقرير الأسبوعي
- آخر يوم في الشهر: بيتبعت كمان التقرير الشهري الكامل بالرسم البياني
- لو ضفت `CRON_SECRET`، الـ endpoint بيتأمّن تلقائيًا (Vercel بيبعت الهيدر ده لوحده مع كل استدعاء مجدول)
- تقدر تغيّر التوقيت أو تفصل الجوبز عن بعض من `vercel.json` براحتك

## 📖 زرار دليل الاستخدام (Telegram Mini App)
- ضفت صفحة `public/guide.html` بتشرح كل أوامر البوت بشكل مرئي، وبتفتح **جوه تليجرام نفسه** كـ Mini App (مش برا في المتصفح)
- الرابط بيتحدد أوتوماتيك من دومين Vercel بتاعك (`GUIDE_URL` مش لازم تحطه يدوي إلا لو عندك دومين مخصص)
- بعد أول Deploy، ابعت `/start` للبوت وهتلاقي زرار "📖 دليل الاستخدام الكامل" تحت الرسالة
- ملحوظة: تليجرام بيشترط إن رابط الـ Web App يبقى **HTTPS**، وده متوفر تلقائيًا مع Vercel

## 📄 التقارير كملفات PDF
- التقرير اليومي (آخر اليوم) والأسبوعي والشهري بقوا كلهم بيتبعتوا كـ **ملف PDF مرفق** بدل رسالة نص طويلة
- بيوصلك الأول رسالة نص مختصرة (الإجمالي + عدد العمليات + أكتر فئة)، وبعدها الملف نفسه فيه كل تفاصيل كل عملية تحت فئتها (مفيش أي قصّ أو اختصار)
- الملف بيتولّد على السيرفر عن طريق `@sparticuz/chromium` + `puppeteer-core` (متوافقين مع Vercel serverless functions)
- ملحوظة مهمة: توليد PDF محتاج ذاكرة ووقت تنفيذ أعلى من العادي — لو خطة Vercel بتاعتك (Hobby) بتوقف الفانكشن بسبب Timeout، هتحتاج تترقّى لخطة Pro أو تراجع القيم في `functions` جوه `vercel.json`

## 💳 الاشتراك الشهري (إنستا باي يدوي)
- **مفيش استخدام مجاني خالص** — أي حد يفتح البوت أول مرة (حتى `/start`) بيلاقي رسالة فيها السعر ورابط الإنستا باي، ومش بيقدر يستخدم أي أمر من غير اشتراك فعّال.
- الدفع يدوي بالكامل، مفيش بوابة دفع مربوطة: المستخدم بيحوّل على `INSTAPAY_LINK` وبيبعت سكرين شوت التحويل (على البوت أو عليك مباشرة عن طريق `ADMIN_CONTACT_USERNAME`).

**تفعيل اشتراك بعد ما تتأكد من التحويل:**
- روح لنفس البوت من حسابك إنت (اللي رقمه في `ADMIN_TELEGRAM_ID`) وابعت:
  ```
  فعل 123456789
  ```
  (رقم الـ `telegram_user_id` بتاع المستخدم — بتلاقيه في لوج الرسايل أو في Supabase جدول `users`)
- لو عايز مدة مختلفة عن الافتراضي (30 يوم مثلًا اشتراك ربع سنوي = 90 يوم):
  ```
  فعل 123456789 90
  ```
- البوت هيرد عليك بتأكيد، وهيبعت للمستخدم نفسه رسالة إن اشتراكه اتفعّل.
- الأمر ده بيشتغل بس لو جاي من `ADMIN_TELEGRAM_ID` بتاعك — أي حد تاني بيتجاهل الرسالة تمامًا.

**التجديد وانتهاء الاشتراك:**
- لو المستخدم اشترك واستخدم البوت، وبعدين خلص الشهر من غير ما يجدد، البوت بيوقف يرد على أي رسالة منه غير رسالة الاشتراك (نفس رسالة أول مرة)، وبيوقف يبعتله تقارير/تذكيرات تلقائية من الـ cron لحد ما يجدد.
- المستخدم يقدر أي وقت يبعت **"اشتراكي"** يشوف حالته وتاريخ الانتهاء بالظبط.
- لو جدد قبل ما اشتراكه يخلص، الأيام الجديدة بتتضاف فوق الباقي (مش بتبدأ من الصفر تاني).
- كل مستخدم اشتراكه هيخلص خلال 3 أيام أو أقل بياخد تذكير تلقائي مرة واحدة من الكرون اليومي.

**مهم:** بعد أي تغيير في `sql/schema.sql`، لازم تروح Supabase → SQL Editor وتشغّل السكريبت تاني (آمن، بيضيف بس العمود الجديد `subscription_expires_at`).

## 👤 صفحة "حسابي" + كشف حساب PDF للديون (المرحلة التانية)
- **كشف حساب PDF عند كتر العمليات:** لو عدد العمليات مع شخص معيّن أكتر من `DEBT_STATEMENT_PDF_THRESHOLD` في `lib/config.js` (افتراضيًا **5**)، أمر `ديون [اسم]` بيبعت ملخص نصي قصير + ملف PDF منظّم لوحده بكل تفاصيل العمليات (منفصل تمامًا عن تقرير المصاريف الشهري). غيّر الرقم في `lib/config.js` وقت ما حبيت.
- **صفحة "حسابي" في الداشبورد:** تاب جديد (`dabbar-dashboard-full.html`) فيه الاسم، الإيميل، حالة ربط تليجرام، وزرار تسجيل خروج، بالإضافة لرفع/قص صورة البروفايل.
- **خطوة إضافية مطلوبة على Supabase:** روح SQL Editor وشغّل `sql/profiles.sql` (بعد `sql/schema.sql` و `sql/linking.sql`). السكريبت ده بيعمل:
  - جدول `profiles` (الاسم، الإيميل، رابط الصورة) مع RLS بحيث كل مستخدم يشوف/يعدّل بس صف نفسه.
  - Storage bucket اسمه `avatars` (عام للقراءة، والرفع/التعديل مقصور على صاحب الحساب بس عن طريق مسار `{user_id}/avatar.jpg`).
  - آمن يتشغّل أكتر من مرة (كله `if not exists` / `on conflict do nothing`).
- صورة البروفايل بتتقصّ من المتصفح (canvas بسيط، بدون أي مكتبة خارجية) قبل ما تترفع — تقدر تسحب الصورة وتزوم عليها قبل الحفظ.

## 🌗 الوضع الفاتح/الغامق (المرحلة التالتة)
- زرار حقيقي في تاب **"حسابي"** بس (مش في أي مكان تاني) — بيبدّل الوضع فورًا وبيحفظه على جهاز المستخدم (`localStorage`)، فلما يفتح الصفحة تاني هيلاقيه فاكر اختياره (وبدون أي فلاش بلون غلط لحظة الفتح).
- الداشبورد (`dabbar-dashboard-full.html`) بقى فيه نسخة فاتحة كاملة من كل الكروت والألوان (خلفيات، حدود، نصوص، تدرجات، شارات) بدل ما الزرار يبقى شكلي من غير معنى.
- **ملحوظة نطاق:** المرحلة دي غطّت صفحة الداشبورد بس (هي الصفحة اللي فيها الزرار). صفحات التسويق/الأونبوردنج (`dabbar-onboarding.html`, `guide.html`, `dabbar-website-premium.html`) لسه بألوانها الغامقة الأصلية زي ما هي — لو عايز نعمل لهم نسخة فاتحة كمان قولّي نبدأ بيها في مرحلة تانية.
- تسجيل الخروج بقى موجود بس جوه تاب "حسابي" (اتشال الزرار العائم اللي كان فوق الصفحة).

## ملاحظات
- الفئات المتاحة حاليًا: أكل، مواصلات، فواتير، تسوق، ترفيه، صحة، أخرى (تقدر تعدلها في `CATEGORIES` بملف `lib/config.js`)
- البوت بيميّز تلقائيًا بين "مصروف" و"دين" و"تسوية دين" عن طريق نفس نموذج الاستخراج
- الديون بتتحسب صافي لكل شخص، وبعد أي تسوية بيبدأ الحساب من تاريخ التسوية (التاريخ القديم بيفضل موجود في `ديون [الاسم]`)
- بنية الكود اتقسّمت لملفات أصغر في `lib/` (تليجرام، Groq، مصاريف، ديون، مستخدمين) بدل ما تكون كلها في ملف واحد
