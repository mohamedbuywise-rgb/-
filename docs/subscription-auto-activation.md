# التفعيل الآلي لاشتراكات InstaPay

## كيف يعمل

1. العميل يحوّل قيمة الاشتراك ويرفع Screenshot من داخل التطبيق.
2. الخادم يحاول استخراج **Reference** و**المبلغ** من الصورة.
3. هاتف صاحب الحساب المستقبِل يرسل SMS البنك إلى:

```text
POST /api/subscription-sms-webhook
Content-Type: application/json

{
  "token": "SUBSCRIPTION_SMS_WEBHOOK_TOKEN",
  "sender": "اسم مرسل البنك",
  "text": "نص SMS البنك كاملًا"
}
```

4. لا يحدث التفعيل إلا إذا تطابق المرجع بعد التطبيع والمبلغ بدقة مع إثبات العميل.
5. إذا وصل أحد الحدثين قبل الآخر، يبقى محفوظًا حتى يصل الحدث الثاني.
6. إذا كان المرجع أو المبلغ غير واضح، تظل الحالة `review` ولا يحدث تفعيل تلقائي.

## متغيرات البيئة المطلوبة

```env
SUBSCRIPTION_SMS_WEBHOOK_TOKEN=سر_طويل_عشوائي_لا_يظهر_لأي_عميل
SUBSCRIPTION_BANK_ACCOUNT_LAST4=1234
SUBSCRIPTION_BANK_SENDERS=InstaPay,IPN,اسم البنك
```

- التوكن يجب تثبيته على هاتف صاحب الحساب فقط، وليس داخل التطبيق أو كود الواجهة.
- `SUBSCRIPTION_BANK_ACCOUNT_LAST4` اختياري، لكنه يضيف قفلًا ثانيًا إذا كان SMS يحتوي آخر 4 أرقام للحساب المستقبِل.
- `SUBSCRIPTION_BANK_SENDERS` اختياري؛ عند ضبطه يتم رفض أي SMS من مرسل غير موجود في القائمة.

## قاعدة البيانات

شغّل مرة واحدة:

```text
sql/subscription-auto-activation.sql
```

## أمان مهم

- لا تستخدم `sms_webhook_token` العام للمستخدمين في هذا التدفق.
- لا يتم قبول صورة العميل كدليل كافٍ وحدها؛ الذكاء الاصطناعي يستخدم لاستخراج المرجع فقط.
- لا يتم قبول SMS من هاتف/توكن غير هاتف صاحب الحساب.
- لا يوجد تفعيل عند اختلاف المرجع أو المبلغ أو عدم وضوحهما.
- كل إثبات وSMS محفوظان بسجل تدقيق، مع بصمة تمنع تكرار نفس الرسالة.
- يجب وضع الخادم خلف HTTPS وعدم تسجيل التوكن أو نص الرسالة في logs العامة.
